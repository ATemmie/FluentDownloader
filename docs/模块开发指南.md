## 1. 模块系统总览

### 1.1 启动时发生了什么

```
App.OnStartup()
  │
  ├─ 1. SettingsService.Load()                    # 读取 %LocalAppData%\FluentDownloader\settings.json
  ├─ 2. ModuleLoader.DiscoverModules()            # ★ 扫描输出目录里的 FluentDownloader.Module.*.dll
  │      └─ 对每个 dll：AssemblyLoadContext.LoadFromAssemblyPath()
  │           → GetTypes() → 找到所有 IModule 实现 → Activator.CreateInstance()
  ├─ 3. foreach module: module.RegisterServices(services)   # 模块向 DI 注册服务/页面/引擎
  ├─ 4. services.BuildServiceProvider()
  ├─ 5. ITaskManager 构造（自动收集所有 IDownloadEngine）
  └─ 6. MainWindow 构造
         └─ foreach module: module.GetPages(sp)   # ★ 把模块页面挂进导航栏
              → NavigationViewItem(Title, Icon, PageType)
```

**关键点：**

- 壳（App）**不引用**任何模块程序集 —— 模块在运行时被发现和加载
- 加载器使用独立的 `AssemblyLoadContext`：模块自己的依赖（如 MonoTorrent）在**应用输出目录**兜底解析；Contracts / Core / WPF-UI 等共享依赖走宿主默认上下文，**保证类型一致**（模块实现的 `IModule` 接口和宿主是同一个类型）
- 删除输出目录里某个 `FluentDownloader.Module.*.dll` → 该模块静默跳过，其它功能不受影响

### 1.2 一次下载请求的旅程

```
用户粘贴链接 / 浏览器嗅探 / 点选模式 / 模块页面
        │
        ▼
ITaskManager.Enqueue(DownloadRequest)
        │
        ▼
TaskManager.Route(request)
        │  在所有 IDownloadEngine 中，取 CanHandle(request) == true
        │  且 Priority 最小的引擎
        ▼
创建 DownloadTask（Pending）→ 加入队列
        │
        ▼  空闲槽位 ≥ 1（MaxConcurrentDownloads，默认 3）
StartLocked(task)
        │  task.Status = Preparing
        ▼
engine.ExecuteAsync(task, pauseToken, cancellationToken)   ← 你的代码从这里开始跑
        │
        ├─ 正常 return            → 任务标记 Completed，触发 TaskCompleted 事件（Snackbar 通知）
        ├─ 抛 OperationCanceled   → 任务标记 Cancelled
        ├─ 抛其它异常             → 任务标记 Failed（ex.Message 显示在卡片上），触发 TaskFailed
        └─ 引擎内部随时可更新     → task.ReceivedBytes / TotalBytes / SpeedBytesPerSecond / Status
                                    （UI 进度条实时刷新）
```

## 2. 三种模块形态

| 形态 | 例子 | 需要 | TargetFramework |
|---|---|---|---|
| **纯引擎**（无界面） | Module.Http | `IModule` + `IDownloadEngine` | `net8.0`（不需要 WPF） |
| **纯界面**（无引擎，借助其它引擎下载） | Module.Browser | `IModule` + 页面，用 `ITaskManager.Enqueue` 添加任务 | `net8.0-windows` + `UseWPF` |
| **引擎 + 界面** | Module.Media / Module.Torrent | 两者都要 | `net8.0-windows` + `UseWPF` |

> 判断标准：你的模块需要"用户输入/浏览/选择"的专属页面吗？只需要"粘贴一个链接就能下"的话，做成纯引擎即可 —— 首页输入框会自动路由给你。

## 4. 完整实战：开发一个 FTP 下载模块

下面以 **FTP 下载模块**（`ftp://` 链接）为例走一遍完整流程，覆盖引擎契约的每个环节。
最终效果：首页粘贴 `ftp://ftp.example.com/pub/file.zip` → 自动路由到 FTP 引擎 → 任务卡片显示进度/速度 → 支持暂停/取消。

### 4.1 项目结构

```
Modules/FluentDownloader.Module.Ftp/
├── FluentDownloader.Module.Ftp.csproj
├── FtpModule.cs            # IModule
├── FtpDownloadEngine.cs    # IDownloadEngine（核心）
└── (可选) FtpPage.xaml/.cs # 如需"FTP 站点浏览"等专属界面再加
```

csproj：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>   <!-- 纯引擎，无需 WPF -->
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="FluentFTP" Version="49.0.2" />
  </ItemGroup>
  <ItemGroup>
    <ProjectReference Include="..\..\FluentDownloader.Contracts\FluentDownloader.Contracts.csproj" />
    <ProjectReference Include="..\..\FluentDownloader.Core\FluentDownloader.Core.csproj" />
  </ItemGroup>
</Project>
```

### 4.2 引擎骨架（重点：契约的每个钩子）

```csharp
using System.IO;
using FluentDownloader.Contracts;
using FluentDownloader.Core;          // SpeedMeter / RateLimiter / FileNameParser / ITaskSpeedSource
using FluentFTP;

namespace FluentDownloader.Module.Ftp;

public sealed class FtpDownloadEngine : IDownloadEngine, ITaskSpeedSource
{
    private readonly ISettingsService _settings;
    private readonly RateLimiter _limiter = new();       // 共享令牌桶（全局限速）
    private readonly SpeedMeter _speed = new();          // 滑动窗口测速
    private long _currentSpeed;

    public FtpDownloadEngine(ISettingsService settings) => _settings = settings;

    // ── 身份 ─────────────────────────────────────────────────────────────
    public string Id => "ftp";                           // 必须稳定！tasks.json 靠它恢复任务
    public string DisplayName => "FTP";
    public int Priority => 50;                           // 数字越小越先接管（http=100 兜底）

    public long CurrentSpeedBytesPerSecond => Interlocked.Read(ref _currentSpeed);
    // ↑ 实现 ITaskSpeedSource 后，首页"全局速度"会自动聚合你的速度

    // ── 路由：我能处理什么请求 ───────────────────────────────────────────
    public bool CanHandle(DownloadRequest request)
    {
        if (request.Url.StartsWith("ftp://", StringComparison.OrdinalIgnoreCase)
            || request.Url.StartsWith("ftps://", StringComparison.OrdinalIgnoreCase))
            return true;
        return false;
        // 注意：不要抢别人的活。return true 前想清楚优先级：
        // media(10) / torrent(10) 都比 50 小，会先于你被匹配。
    }

    // ── 执行：整个下载生命周期 ───────────────────────────────────────────
    public async Task ExecuteAsync(DownloadTask task, PauseToken pause, CancellationToken ct)
    {
        Directory.CreateDirectory(task.SaveDirectory);

        // 1) 探测（可选）：拿文件大小，让进度条有分母
        task.Status = DownloadTaskStatus.Preparing;
        var uri = new Uri(task.Url);
        var remotePath = uri.AbsolutePath;

        using var client = new AsyncFtpClient(uri.Host, "anonymous", "anonymous@mail.com");
        await client.Connect(ct);

        task.TotalBytes = await client.GetFileSize(remotePath, -1, ct);

        // 2) 决定落盘文件名（只在此处做一次，避免重名覆盖）
        var name = FileNameParser.Sanitize(
            task.Options.TryGetValue("fileName", out var n) ? n : Path.GetFileName(remotePath));
        task.FileName = FileNameParser.EnsureUnique(task.SaveDirectory, name);
        var targetPath = task.FullPath;

        // 3) 状态切到 Downloading（UI 进度条开始工作）
        task.Status = DownloadTaskStatus.Downloading;
        _speed.Reset();

        // 4) 下载主循环：暂停 / 限速 / 进度 / 测速 四件套
        var progress = new Progress<FtpProgress>(p =>
        {
            task.ReceivedBytes = (long)p.TransferProgressToFilePosition;
            var s = _speed.Update(task.ReceivedBytes);
            Interlocked.Exchange(ref _currentSpeed, s);
            task.SpeedBytesPerSecond = s;
        });

        try
        {
            await client.DownloadFile(
                localPath: targetPath, remotePath: remotePath,
                existsMode: FtpLocalExists.Overwrite, verifyOptions: FtpVerify.None,
                progress: progress, token: ct,
                pauseToken: pause);   // ← FluentFTP 原生支持 PauseToken，别的能力用 §5.3 的轮询模式

            task.ReceivedBytes = task.TotalBytes;
            task.SpeedBytesPerSecond = 0;
        }
        finally
        {
            await client.Disconnect(ct);
            // 若实现了 checkpoint，这里统一清理/保留
        }
        // 正常 return → TaskManager 标记 Completed
    }
}
```

> **没有原生 PauseToken 支持的库？** 用契约层的轮询模式，在任何循环里插入：
> ```csharp
> await pause.WaitWhilePausedAsync(ct);   // 暂停期间在此等待；ct 取消时抛 OCE
> ```
> 建议每读/写一个数据块调用一次，暂停响应延迟 ≤ 一个块的处理时间。

## 5. 契约参考手册

### 5.1 `IModule`（FluentDownloader.Contracts）

| 成员 | 类型 | 语义 |
|---|---|---|
| `Id` | `string` | 模块唯一标识。建议小写、与程序集名对应（`http` / `media` / `torrent` / `ftp`） |
| `DisplayName` | `string` | 导航栏 / 引擎徽标显示名（中文） |
| `IconGlyph` | `string` | `Wpf.Ui.SymbolRegular` 枚举名，如 `"Globe24"`；解析失败回退 `Fluent24`。图标一览：https://api.fluenticons.co |
| `NavigationOrder` | `int` | 导航排序。**< 0 = 不出现在导航栏**；核心页占 0（首页）/ 5（任务），设置固定在 Footer；模块请从 **10** 起用（现有：browser=10, media=20, torrent=30） |
| `RegisterServices(IServiceCollection)` | void | 注册页面、ViewModel、引擎、私有服务。宿主会传入全局容器 |
| `GetPages(IServiceProvider)` | `ModulePageDescriptor[]` | 返回要挂导航的页面；可为空数组 |
| `GetEngines(IServiceProvider)` | `IDownloadEngine[]` | 返回引擎实例；可为空数组 |

`ModulePageDescriptor(string Title, string IconGlyph, Type PageType)` —— `PageType` 必须已通过 `RegisterServices` 注册进 DI（导航时由容器解析实例，建议**单例**）。

### 5.2 `IDownloadEngine`

```csharp
public interface IDownloadEngine
{
    string Id { get; }                       // 引擎标识，持久化任务依赖它，发布后不可改名
    string DisplayName { get; }              // 任务卡片上的引擎徽标
    int Priority { get; }                    // 路由优先级，越小越先
    bool CanHandle(DownloadRequest request); // 是否接管该请求
    Task ExecuteAsync(DownloadTask task, PauseToken pause, CancellationToken ct);
}
```

**`ExecuteAsync` 退出语义（必须遵守）：**

| 你的行为 | TaskManager 的解读 | UI 表现 |
|---|---|---|
| 正常 `return` | Completed | 绿色 Snackbar + 完成态按钮 |
| 抛 `OperationCanceledException` | Cancelled | 可点"继续"重跑 |
| 抛其它异常（建议 message 用中文、说人话） | Failed | 红字显示 `ex.Message`，可点"继续"重跑 |
| 内部 `while` 等待 `pause` | —（任务留在 Downloading，外部 Pause 已把状态改为 Paused） | 进度冻结 |

**状态机**（由 TaskManager 与引擎共同驱动）：

```
Pending → Preparing → Downloading → Completed
                │          │
                └──→ Paused ←┘      Failed / Cancelled（均可"继续"重新入队）
```

引擎负责 `Preparing → Downloading` 的切换；暂停/恢复/取消由 TaskManager 调用方触发，
引擎只需**响应** `pause` 与 `ct`。

### 5.3 `DownloadTask` —— 引擎驱动 UI 的唯一通道

| 属性 | 谁写 | 说明 |
|---|---|---|
| `Status` | 引擎写 `Preparing`/`Downloading`；TaskManager 写其它 | 状态机见上 |
| `TotalBytes` | 引擎 | 探测到的总大小；**0 = 未知**（进度条自动转不确定动画） |
| `ReceivedBytes` | 引擎 | 每收到一块就更新（绑定驱动，无需节流） |
| `SpeedBytesPerSecond` | 引擎 | 用 `SpeedMeter` 平滑后再写，避免 UI 数字抖动 |
| `Title` | 引擎 | 媒体任务 = 视频标题；直链 = 文件名。卡片主标题 |
| `FileName` / `SaveDirectory` | 引擎（入队时可预设） | `FullPath` = 二者拼接；完成后"打开文件夹"靠它 |
| `QualityLabel` | 引擎 | 徽标文本，如 `1080P`、`BT · 12 做种 / 3 下载中` |
| `ErrorMessage` | 引擎（可省） | Failed 时 TaskManager 自动写入 `ex.Message` |
| `Options` | 入队方 | 引擎私有参数字典（如媒体任务的 `selector` / `audioOnly`） |
| `Referrer` / `CookiesFilePath` | 入队方 | 来源页与 cookies（浏览器模块自动带上） |

> 属性变更通知已内置（`ObservableModel`），引擎在后台线程直接赋值即可，
> WPF 标量绑定会自动跨线程封送。**但绝不能在后台线程增删 `ITaskManager.Tasks` 集合** ——
> 一律走 `Enqueue` / `Remove`（内部已做 UI 线程封送）。

### 5.4 `DownloadRequest`（添加任务的入参）

| 属性 | 说明 |
|---|---|
| `Url` | 必填。磁力链、`ftp://`、网页链接、直链…… |
| `KindHint` | 路由提示：`Auto`（按 URL 特征让引擎抢）/ `DirectLink`（强制 HTTP）/ `MediaStream`（强制 m3u8→媒体）/ `MediaPage` / `Torrent` |
| `FileName` | 指定文件名；空则引擎探测（`Content-Disposition` → URL 末段） |
| `SaveDirectory` | 空则用全局设置 `Settings.DownloadDirectory` |
| `Options` | 引擎私有参数，会随任务持久化（重启恢复后仍在） |
| `CookiesFilePath` | Netscape 格式 cookies（内置浏览器"同步 Cookies"导出的路径在 `Settings.CookiesFilePath`） |

### 5.5 路由规则与优先级约定

TaskManager 的路由一句话：**`CanHandle` 为 true 的引擎里取 `Priority` 最小的**。

当前占用：`media=10`、`torrent=10`、`http=100`（兜底）。建议约定：

- 专属协议引擎（ftp / sftp / ed2k / 网盘直链…）：`10 ~ 90`
- 通用兜底引擎：`>= 100`
- 不要让两个引擎对同一 URL 都返回 true 还都是低数值 —— 先到先得，用户会困惑

`HttpDownloadEngine.CanHandle` 的兜底逻辑（供参考）：`KindHint` 不是
MediaStream/MediaPage/Torrent，且 scheme 是 http/https → 接管。

### 5.6 `ITaskManager`（模块添加任务的标准入口）

```csharp
DownloadTask Enqueue(DownloadRequest request);  // 路由失败抛 NotSupportedException（含中文说明）
void Pause/Resume/Cancel/Remove(DownloadTask task);
void RevealInExplorer(DownloadTask task);        // 资源管理器定位文件
ObservableCollection<DownloadTask> Tasks { get; }          // 只读使用，别直接 Add/Remove
long GlobalSpeedBytesPerSecond { get; }                    // 聚合所有实现了 ITaskSpeedSource 的引擎
event EventHandler<DownloadTask> TaskCompleted / TaskFailed;
```

### 5.7 `ITaskSpeedSource`（FluentDownloader.Core，可选实现）

实现它并在引擎里维护 `CurrentSpeedBytesPerSecond`，首页"全局速度"卡片就会聚合你的引擎。
参照 `HttpDownloadEngine`：`Interlocked.Exchange(ref _currentSpeed, speed)`。

### 5.8 `ISettingsService` / `AppSettings`

```csharp
Settings.DownloadDirectory        // 全局下载目录（任务的默认落盘位置）
Settings.MaxConcurrentDownloads   // 全局并发任务数（TaskManager 自动遵守，引擎无需关心）
Settings.CookiesFilePath          // 浏览器模块导出的 cookies
AppSettings.DataDirectory         // %LocalAppData%\FluentDownloader\（tasks.json、cookies.txt）
AppSettings.BinariesDirectory     // %LocalAppData%\FluentDownloader\bin\（yt-dlp.exe 等）
```

模块专属设置：简单场景读写自己的 JSON 放 `AppSettings.DataDirectory` 即可；
要进设置页则在 `AppSettings` 加属性 + `SettingsPage.xaml` 加控件（这属于改动共享代码，尽量克制）。

## 6. 可复用的基础设施

全部位于 `FluentDownloader.Core`，模块可直接 `using FluentDownloader.Core;`：

| 类 | 用途 | 典型用法 |
|---|---|---|
| `RateLimiter` | 共享令牌桶限速 | `await limiter.AcquireAsync(read, bytesPerSecond, ct);`（写在写盘前） |
| `SpeedMeter` | 指数滑动平均测速 | `var speed = meter.Update(totalBytesNow);`（输出平滑速度，避免 UI 抖动） |
| `FileNameParser` | 文件名解析三件套 | `FromContentDisposition` / `FromUrl` / `Sanitize` / `EnsureUnique`（Windows 非法字符、保留名、重名 `(1)`） |
| `FormatUtils` | 字节/速度/剩余时间格式化 | 设置页与卡片文本用 |
| `TaskManager` | 见 §5.6 | 经 DI 注入 `ITaskManager` 使用 |

**文件名规范（强烈建议照抄 HTTP 引擎的做法）：**

1. 只在下载开始时决定一次文件名（续传时不能变，否则找不到断点文件）
2. `Sanitize` 清洗 → `EnsureUnique` 防覆盖 → 赋给 `task.FileName` → 用 `task.FullPath`

## 7. 常见 陷阱（真实踩坑记录）

以下每一条都在本项目开发中实际发生过，请通读一遍再动手：

### 7.1 用标准 `<Page>`，不是 `ui:Page`
WPF-UI 4.x 移除了 `Wpf.Ui.Controls.Page`。页面根元素写 `<Page>`（System.Windows.Controls.Page），
`Background="Transparent"` 保持 Mica 透出。

### 7.2 下载完成后任务卡在"Downloading"
**本项目第一个真实 bug**。HTTP 引擎曾有一个"周期落盘 checkpoint"的后台循环，
只在任务取消时退出；`await` 它导致 `ExecuteAsync` 永不返回 → 任务永远到不了 Completed。
**教训**：`ExecuteAsync` 里的任何子任务（persist / watchdog / 心跳）都必须有明确的退出条件，
且正常完成路径上不能 await 一个"永不结束"的任务。
推荐模式：`using var cts = CancellationTokenSource.CreateLinkedTokenSource(ct);`
工作完成后 `cts.Cancel()` 再 await 收尾。

### 7.2.1 WPF-UI 4.3.0 Snackbar 彩色外观渲染成空盒
**本项目第二个真实 bug**。`SnackbarService.Show(..., ControlAppearance.Success, ...)`
弹出的通知只有绿色空壳、没有任何文字（Secondary 外观正常）。
根因：Success/Danger 等触发器依赖 `Palette*Color` 动态资源与彩色样式变体，
在 4.3.0 + 本项目主题组合下文本渲染异常。
**修复**：弃用 SnackbarService，在 MainWindow 自绘轻量 Toast
（Border + 左侧色条 + 标题/消息 + 淡入滑出动画，见 `MainWindow.xaml` 的 `ToastBorder`）。
**教训**：第三方控件库的次要控件（通知类）升级后行为易变；视觉反馈这类高可见度 UI
值得自己掌控，或升级依赖版本时必须逐外观回归验证。

### 7.3 模块 dll 找不到 / 模块没被加载
- `Assembly.Load(name)` **不会**按输出目录探测（默认上下文严格按 deps.json 解析）——
  这就是 `ModuleLoader` 用 `AssemblyLoadContext.LoadFromAssemblyPath` + `Resolving` 事件的原因。
  新模块不要绕开加载器自己 Load。
- 模块的 NuGet 依赖要出现在应用输出目录：`Directory.Build.props` 已全局开启
  `CopyLocalLockFileAssemblies=true`，App 的 `CopyModuleOutputs` Target 负责复制 ——
  **新模块必须加进该 Target 的路径列表**（§3 第 4 步 ③），否则运行时缺依赖、模块被静默跳过。

### 7.4 后台线程操作任务集合导致 UI 崩溃
`ObservableCollection` 只能在 UI 线程改。浏览器嗅探等异步回调里要加任务时，
调 `ITaskManager.Enqueue`（内部封送），不要 `Tasks.Add(...)`。

### 7.5 文件名没有防重名 / 非法字符
Windows 保留名（CON、NUL…）、结尾空格点、`Content-Disposition` 的 `filename*=UTF-8''` 编码……
全部已由 `FileNameParser` 处理。自己拼文件名之前先调它。

### 7.6 引擎 Id 改名导致旧任务复活失败
`tasks.json` 里存的是 `EngineId`。发布后修改引擎 Id，旧任务重启恢复时会报
"对应的下载模块未加载"。Id 一经发布，只增不改。

### 7.7 续传不校验资源变更
断点续传前必须验证"还是同一个文件"（ETag / Last-Modified / Content-Length 至少比对一项，
续传请求带 `If-Range`）。否则服务器文件更新后会拼出损坏文件。参照 `ResourceChanged()`。

### 7.8 服务器不支持 Range
凡是假设"一定能分段"的代码都会在这里炸。探测到 `Accept-Ranges` 缺失或首段返回 200 时，
必须降级单流（HTTP 引擎的 `DownloadSingleStreamAsync` 是现成参照）。

### 7.9 期望"毫秒级暂停"
暂停靠 worker 循环里的 `pause.WaitWhilePausedAsync(ct)`，响应粒度 = 一次循环迭代。
把检查点放在**每个数据块**的处理循环里，而不是整个段的开头/结尾。

### 7.10 外部进程引擎（yt-dlp 等）的暂停
外部进程不支持暂停语义。Media 模块的做法：检测到 `pause.IsPaused` → 杀进程；
恢复时重新拉起（yt-dlp `--continue` 天然续传）。这是外部进程类引擎的推荐模式。
